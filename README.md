# SHOTGUARD

**中文** | [English](README.en.md)

> **AI 视频自动验收工具——你给视频，它告诉你哪里崩了。**

所有 AI 视频平台（可灵 / 即梦 / Seedance / Runway / Vidu）都只解决"**怎么生成得更好**"，
没有一家解决"**生成的这条到底有没有崩**"。

SHOTGUARD 补的就是这一环：**生成之后的验收**。

---

## 先说清楚：这工具什么时候没用

这个项目的起点是一个真实质疑：

> **"人物和画面崩没崩，肉眼看得出来吧？"**

**这个质疑基本是对的。** 所以先把适用边界说清楚：

| 你的情况 | 这个工具 |
|---|---|
| 月产 5–10 条，单人物、短视频，有时间逐帧看 | ❌ **用不上，人眼够了** |
| 细微漂移（该是沙发的地方变成了床、发夹换了边） | ✅ 有用，**人会脑补着忽略掉** |
| 跨镜连续性（前后帧对比才能发现的不一致） | ✅ 有用，**单看任何一帧都是"对的"** |
| 批量交付，月产 50 条以上 | ✅ 有用，**人看不过来** |

**它不是替代你的眼睛，而是在你会漏的地方补一刀**：细微处、跨镜处、以及量大到看不过来的时候。

> 真实数据见 [`cases/`](cases/)：三个真实样本，包括"写得最好的结构化提示词"也照样崩。

---

## 检测什么

8 类崩坏，逐帧检测：

| 崩坏类型 | 说明 |
|---|---|
| 身份漂移 | 人脸、发型、服装与参考图不一致 |
| 服装漂移 | 服装款式、颜色、穿着状态变化 |
| 道具漂移 | 道具凭空出现或消失 |
| 空间漂移 | 场景结构（门窗、家具、左右关系）变化 |
| 光线漂移 | 光源方向、阴影方向变化 |
| 状态回滚 | 天气、时间、破损等状态被无理由改变 |
| 动作断链 | 空镜（画面里没有人）或动作不连贯 |
| 声音断链 | ⚠️ 暂不支持（需要音频分析） |

## 快速开始

### 需要准备

1. 一段 AI 视频（MP4 / MOV / WebM）
2. 一张角色参考图
3. 两句话描述（角色长什么样 + 场景什么样）
4. 一个**支持读图的**视觉模型 API（OpenAI 兼容）

### 方式一：命令行（完整功能）

```bash
# 配置 API（一次性）
export VISION_API_BASE_URL="https://api.openai.com/v1"
export VISION_API_KEY="sk-..."
export VISION_MODEL="gpt-4o"

# 跑验收
node src/shotguard-verify.js "video.mp4" "character.png" "角色描述" "场景描述"
```

**产出两份报告：**

- `verify_report.json` — 结构化数据，供程序消费
- `verify_report.html` — **可直接交付给甲方的报告**（内嵌逐帧截图，单文件、约 5 MB、无外部依赖）

### 不想自己准备素材？

[`demo/`](demo/) 目录内置**真实测试素材**（同一角色、同一场景、三种提示词写法），无需准备任何东西即可跑通：

```bash
cd demo
node ../src/shotguard-verify.js \
  case-a-naive-prompt.mp4 \
  reference-character.png \
  "17岁少女，黑色长直发及肩，右侧银色发夹，米色针织开衫内搭白衬衫，眼下有淡雀斑" \
  "木质地板，白色墙面，右侧一扇落地窗，窗下有灰色布艺沙发"
```

三组提示词的完整全文与预期结果见 [`demo/README.md`](demo/README.md)。

### 方式二：浏览器

直接打开 [`index.html`](index.html)，填表即可。

> ⚠️ 浏览器无法直接调用 ffmpeg 抽帧，网页版是**轻量演示**。完整功能请用命令行版。

## API 兼容性

需要**视觉理解（能读图）**的 API，OpenAI 兼容格式即可：

| 服务 | API 地址 | 模型示例 |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o` |
| Claude | `https://api.anthropic.com/v1` | `claude-3-5-sonnet` |
| Qwen-VL | `https://dashscope.aliyuncs.com/v1` | `qwen-vl-max` |
| Gemini | `https://generativelanguage.googleapis.com/v1` | `gemini-pro-vision` |
| 豆包视觉 | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-vision` |
| 本地部署 | 自填 | 自填 |

**不支持**纯图像生成 API（DALL·E、Midjourney 等）——它们只能生图，不能读图。

## 真实案例

三个样本用的是**同一个角色、同一个场景、同一个动作**，唯一差异是提示词写法：

| 案例 | 提示词 | 检测结果 | 报告 |
|---|---|---|---|
| **A** | 普通写法（18 字） | 4 类崩坏（身份/道具/空间/光线） | [HTML](cases/case-a-naive-prompt.html) |
| **B** | 等长非结构化（568 字，只堆气氛） | 模糊帧占比高，多处无法判定 | [HTML](cases/case-b-long-unstructured.html) |
| **C** | 结构化（588 字，含场景锚点/指纹锁） | **仍检出 3 类崩坏** | [HTML](cases/case-c-structured-prompt.html) |

**案例 C 是重点**：即使是写得最好的结构化提示词，**也无法 100% 防止崩坏**。

这也印证了 PersonaShot 论文（[arXiv:2608.16717](https://arxiv.org/abs/2608.16717)）的结论——
跨镜头一致性相比单镜头，视觉质量衰减约 25%、情绪表达衰减约 50%，论文原话：
"*Even visually compelling videos frequently exhibit physical-state resets.*"

**连最好的提示词也需要验收。**

> 案例报告体积较大（各约 5 MB），因为内嵌了全部帧截图，以便单文件交付给甲方。

## 已知限制

1. **声音断链不支持** — 只做视觉检测，音频分析未实现
2. **模糊帧无法判定** — 过暗 / 过模糊的帧会被标记为"无法判断"，而不是强行给结论
3. **背身帧部分维度不可判** — 人脸不可见时，身份漂移只能靠发型 / 服装推断
4. **模型限流** — 已内置 429 指数退避重试与请求间隔；批量处理时请留出配额
5. **置信度会波动** — 报告里的"置信度"= 成功判定帧数 / 总帧数，低置信度意味着样本质量不够

## 技术实现

- **抽帧**：ffmpeg / ffprobe（均匀取 N 帧，默认 6 帧）
- **检测**：把「参考图 + 当前帧」一起喂给视觉模型，要求返回结构化 JSON
- **容错**：模型返回空内容时标记为"无法判断"，而非误判
- **限流**：429 指数退避（2s → 4s → 8s，最多 3 次）+ 帧间 1.5s 间隔
- **报告**：JSON + 自包含 HTML（base64 内嵌图片，单文件可交付）

## 背景

这个项目源于一次完整的自我证伪过程。

最初的设想是"卖提示词工程化服务"，但在做市场尽调时发现：
唯一的学术支撑被断章取义、替代品（397B 的提示词增强模型）已经免费且更强、
定价高于真实市场一个数量级。

**于是推翻了原方案，转向了平台都不做的这一环：生成后的验收。**

完整的过程记录（包括失败的部分）保留在项目的历史文档中——
因为一个被证伪的假设，比一个没被验证的假设更有价值。
